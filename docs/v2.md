# PepTrack v2

Log book for weekly incretin doses. One Google login, one or more people, one current vial per person. Inventory is a convenience, not a ledger.

Written against the shipped app at `0.3.5-close-vials` (`APP_VERSION` **v0.3.5**). Current behavior stays in [DESIGN.md](DESIGN.md). This document is the product contract. The orchestrator queue is [v2-checklist.md](v2-checklist.md). Milestone results go in [v2-milestones.md](v2-milestones.md).

This plan does not change the app and does not bump `frontend/src/lib/version.ts`. Implementation milestones bump the version as the checklist names, from **v2.1.0** through **v2.5.0**.

## What changes

v0.3.5 asks the user to run an inventory: Home remainder, a log wizard, a History tab, and separate stock for vials, bacteriostatic water, and syringes, with archive lists, manual adjustments, and overdraw rejection.

v2 keeps a record of every dose and shows the vial they are drawing from now.

| | v0.3.5 | v2 |
| --- | --- | --- |
| Default screen | Home remainder | Log |
| Tabs | Home, Log, Inventory, History | Log, Inventory, Settings |
| People | Profiles, capped, default required, vial mismatch blocked | Names on the login. One or more. Any person can draw any current vial |
| New dose | Wizard, then IU | One screen, prefilled from that person's latest dose, date is today |
| Calculator | Page-adjacent on the mix form | Modal over the vial form |
| Stock | Vials + BAC bottles + syringe counts, open/archived, full lists | The current vial, and how much of it each assigned person has logged |
| Empty vial | Remaining math, archive when zero | User marks **Last draw**. The app says the vial is probably empty and offers a new one |
| Enforcement | 422 on overdraw, adjustments, archive rules | None. A dose always saves |

People are names inside one account. They are not separate logins and they do not get their own database file.

## Stack (kept)

Stay on the current architecture. v2 replaces the domain and the screens.

| Layer | Choice |
| --- | --- |
| API | Slim 4, PHP 8.3+, PHP-DI. JSON under `/api/v1` |
| SPA | SvelteKit + `adapter-static`. Client routes only. Build into `backend/public/` |
| Session | Cookie `cimtapp_session`. Same origin. Google authorization code + PKCE |
| Global store | `data/global.sqlite` — users, sessions, wrapped DEKs |
| User store | `data/users/{uuid}.sqlite.enc` — people, vials, log, peptides, lid colors |
| Crypto | Unchanged. [DESIGN.md](DESIGN.md) encryption stance still applies |
| Phone | 360px floor, 430px column, 48px targets, 16px inputs, bottom tabs, safe area |

Google sign-in finds the account by verified email or creates it, which finds or creates that user's encrypted sqlite. That file is per login, not per person.

Password login stays on the server so existing accounts still open. The login screen keeps **Continue with Google** as the action, with email behind the existing secondary control. v2 adds no password UX.

Export of the decrypted sqlite and the pre-migration `.enc.bak` stay.

## Screens

Login has no tabs. Everywhere else: **Log**, **Inventory**, **Settings**. Log is `/` and the emphasized tab.

Settings is a tab, not a gear buried on Home. Home and History go away. Past doses are the list on Log.

### Log `/`

One screen. A returning person with a vial and a previous dose can save without visiting another route.

```
[Noah] [Sam] [+]
Mon, Nov 16                  ← date, default now
Tirzepatide - Noah - 0.05 mg/IU
Blue
[ 25 ] IU
2.50 mg · 0.25 mL
[ ] Last draw
Same as Nov 9
[ Save ]

Nov 9     25 IU · 2.50 mg
Nov 2     25 IU · 2.50 mg
```

- **Person chips.** The selected person owns this entry (the dose went into them). Remember the last chip in `localStorage` under `peptrack.person`. One person: select them. Several, and nothing remembered: the earliest person.
- **+** opens a name modal, saves the person, and selects them.
- **Date** defaults to now in `datetime-local`. The user can move it to backfill. The prefill source does not change the date.
- **Vial** defaults to that person's current vial. The list is every current vial in the account, including vials assigned to someone else. Choosing another person's vial does not reassign it. It records that this person drew from that vial.
- **IU** is the only dose field. Milligrams and milliliters are computed. The IU text is selected on focus so a weekly repeat is Save, and a change is type-and-Save. Small − / + steps of 0.5 IU stay beside the field.
- **Last draw** is off unless the source entry had it on. The user opts in.
- **Same as {date}** shows when a source entry exists. The source is that person's latest log row, by `logged_at` then id. A newer correction wins over an older weekly dose. There is no search for "the row closest to seven days ago."
- **Recent list** is that person's log, newest first. Tap a row to edit at `/log/{id}` using the same form. Delete sits on the edit screen behind one confirm.
- **Syringe** is not on this form. The account syringe (Settings) is snapshotted onto a new row. An edited row keeps the syringe snapshot it was saved with.

Empty states, still on this screen:

| State | What the screen shows |
| --- | --- |
| No people | Name field and Add. No dose form |
| Person, no current vial | **Make a vial** opens the vial modal. Save stays off until a vial exists |
| Selected vial's latest log row has Last draw | Banner: "This vial is probably empty." Actions: **Recompound** and **Recalculate** |

Save is enabled when a person, a current vial, and an IU greater than 0 with at most one decimal are present. Remaining amount does not affect Save.

### Inventory `/inventory`

Current vials only. One card per vial that is still current.

```
Tirzepatide - Noah, Sam - 0.05 mg/IU
Blue
7.50 mg left
Noah 5.00 mg · Sam 2.50 mg
Probably empty

[ New vial ]
```

- The title is the derived name.
- Lid color is a text line. Migrated vials with no color say **No lid color**.
- **mg left** = labeled peptide mg − usage offset − sum of `dose_mg` on log rows for this vial. The offset is 0 for vials created in v2. See migration for old adjustments.
- When more than one person is on the vial, a second line shows each person's summed `dose_mg`.
- A negative result reads **{mg} mg past the label**. The card stays. Nothing asks the user to fix it.
- **Probably empty** shows when that vial's latest log row has Last draw set.
- **New vial** and a card's **Replace** open the same vial modal. Replace prefills that vial.
- There is no full list, no archive, no BAC section, no syringe stock, no edit of historical vials.

### Settings `/settings`

- **People.** Add, rename, remove, restore. A removed person leaves the chips and is unassigned from the current vial. Past log rows keep the snapshotted name. Removed people sit under **Removed** with Restore. Removing the last person is allowed; Log returns to the add-person state.
- **Peptides.** Seeded **Tirzepatide** and **Retatrutide**. Add a name. Remove hides it from the vial modal. A peptide on a current vial or on any log row can be hidden from the picker and still displays on those rows via the snapshot.
- **Syringe.** One account syringe. Seed **0.5 mL / 50 IU**. Change is two numbers. This is the IU ruler for new log rows and for pepcalc. It is not stock.
- **Account.** Email, export, log out, app version.

### Vial modal

Shared by Inventory (**New vial**, **Replace**) and Log (**Make a vial**, **Recompound**, and the step after **Recalculate**). One `ModalSheet`. Pepcalc replaces the body of that same sheet and returns to the vial fields. It does not stack a second sheet.

Fields:

| Field | Rule |
| --- | --- |
| Peptide | Settings list. Required |
| People | One or more. Order is the order checked. Required |
| Peptide mg | Greater than 0. Milligrams in the vial |
| BAC mL | Greater than 0 |
| Lid color | Typeahead of existing colors. A typed name with no case-insensitive match offers **Add "{name}"**. The color is created when the vial saves, not when the modal opens. Required for vials created here |
| Name | Read-only preview |

**Calculate** swaps the sheet to pepcalc. **Use this mix** writes peptide mg and BAC mL back and returns to the vial fields.

Save assigns this vial as the current vial for every selected person. Each of those people loses their previous current vial. A previous vial with nobody left on it leaves Inventory. Log rows that cited it stay, with their own snapshots.

**Recompound** opens the modal filled from the current vial: peptide, mg, BAC, people in saved order, lid color. **Recalculate** opens pepcalc first, with vial mg, the person's latest dose mg, and latest IU. Applying it lands in the vial modal with the new BAC, same people and lid.

### Pepcalc modal

Helper only. It never writes a vial by itself.

Inputs, prefilled when the caller has them:

- mg per vial
- target mg per dose
- target IU per dose
- syringe mL and IU (account syringe)

Output uses the existing `waterNeededPerBottle` math:

```
shot_ml       = target_iu × (syringe_ml / syringe_iu)
bac_water_ml  = peptide_mg × shot_ml / target_mg
concentration = peptide_mg / bac_water_ml
```

Show BAC mL, concentration, and the target as "{mg} mg at {IU} IU". Concentration outside 0.5–20 mg/mL shows the existing warning copy and still allows **Use this mix**.

Changing the syringe inside pepcalc changes that calculation. It does not change the account syringe unless the user edits Settings.

### Login `/login`

**Continue with Google** is the primary control. Email and password stay behind the secondary control already shipped. New Google email → user row, DEK, encrypted sqlite, seeded peptides, seeded syringe, zero people. Existing email → that file, unchanged people and log.

## Derived vial name

```
{Peptide} - {People joined with ", "} - {concentration}
```

Concentration uses `formatConcentration` (`5.00 mg/mL`, or three decimals when the third digit matters).

Examples:

- `Tirzepatide - Noah - 0.05 mg/IU`
- `Retatrutide - Noah, Sam - 0.10 mg/IU`

The name is stored on the vial and copied onto each log row. Renaming a person does not rewrite old log rows. It does rewrite the current vial's display name, because that name is a label for the vial in hand.

## Dose math

Same formulas as [DESIGN.md](DESIGN.md). Do not assume U-100. The syringe on the row is `(volume_ml, capacity_iu)`.

```
concentration = peptide_mg / bac_water_ml
volume_ml     = iu × (syringe_volume_ml / syringe_capacity_iu)
dose_mg       = volume_ml × concentration
mg_left       = peptide_mg − usage_offset_mg − Σ dose_mg for this vial
```

Store mg at 4 decimal places. Display mg with the existing `formatMg`. IU allows one decimal and must be greater than 0.

Worked example: 10 mg in 2.0 mL, syringe 0.5 mL / 50 IU, 25 IU → 5.00 mg/mL, 0.25 mL, 1.25 mg.

`mg_left` is display. It may be negative. The server accepts the log either way. There is no `remaining_iu` error and no adjust endpoint.

## Last draw

A log row has `is_last_draw`. The vial is **probably empty** when its latest row (by `logged_at`, then id) has `is_last_draw` true.

That flag is the only empty signal. Remaining math does not set it. Saving a newer row with Last draw off clears the banner. Replacing the vial removes it from Inventory, banner included.

The banner's two actions:

| Action | Opens with |
| --- | --- |
| Recompound | Vial modal, previous mix unchanged |
| Recalculate | Pepcalc with previous vial mg and this person's latest dose mg and IU, then the vial modal |

The user can ignore the banner and log another dose against the same vial.

## What a log row stores

Enough to rebuild the dose after the vial is gone.

| Column | Meaning |
| --- | --- |
| id | UUID |
| person_id | Who received the dose. Nullable if that person row is later deleted; the snapshot remains |
| person_name | Snapshot |
| vial_id | Vial drawn from. Nullable if that row is gone |
| vial_name | Snapshot of the derived name |
| lid_color_name | Snapshot, empty string when the vial had none |
| peptide_name | Snapshot |
| bac_water_ml | BAC in that vial |
| peptide_mg_in_vial | Milligrams compounded into that vial |
| concentration_mg_per_ml | `peptide_mg_in_vial / bac_water_ml` at save time |
| iu | Drawn |
| dose_volume_ml | Computed |
| dose_mg | Computed. What went into the person |
| syringe_volume_ml, syringe_capacity_iu | Snapshot |
| logged_at | When the dose happened |
| is_last_draw | User said this was the last draw |
| notes | Optional. Collapsed on the form. Empty stays null |
| created_at, updated_at | Bookkeeping |

Editing IU recalculates `dose_volume_ml` and `dose_mg` from the row's syringe snapshot and the selected vial's concentration. Editing the vial re-snapshots that vial's name, lid, peptide, BAC, vial mg, and concentration. Editing the person re-snapshots the person name. The account syringe is not consulted on edit.

Deleting a row removes that dose from `mg_left`. It does not restore a superseded vial.

## Current vial rules

- A person has at most one current vial.
- A vial has one or more people, in an explicit order, used in the derived name.
- Inventory lists vials whose `superseded_at` is null.
- Saving a vial for a person sets `superseded_at` on the vial that was current for them, after removing them from it. If anyone remains on the old vial, it stays current for those people and its derived name updates.
- Superseded vials are not listed and have no edit screen. Rows stay in sqlite so `vial_id` on old log entries still resolves. The product surface is one vial deep.
- Drawing from someone else's current vial does not change who the vial is assigned to.

`usage_offset_mg` is a migration leftover so today's corrected remainders still display. New vials store 0. No API writes it.

## Schema

User-store format **v8** (`UserStoreFormat::V8LogBook`), applied with the existing strategy catalog on unlock. Additive. v8 adds the log-book tables below and does not rename or drop v0.3 tables. Old routes keep reading `profiles`, `compounds`, `uses`, `bac_bottles`, `syringe_profiles`, and `user_peptide_types` until milestone M5. New routes read only the v8 tables. There is no dual-write.

New and rewritten shapes:

**people** — new table, backfilled from `profiles`. `id`, `name`, `created_at`, `removed_at` nullable. Visible names unique, case-insensitive. No default-profile requirement. No maximum count.

**peptides** — new table, backfilled from `user_peptide_types` using migration step 2. `id`, `name`, `slug`, `removed_at`. Seed Tirzepatide and Retatrutide on new accounts.

**lid_colors** — new table. `id`, `name` unique case-insensitive, `created_at`.

**vials** — new table, backfilled from `compounds`. `peptide_mg`, `bac_water_ml`, `concentration_mg_per_ml`, `display_name`, `lid_color_id` nullable, `lid_color_name`, `usage_offset_mg`, `compounded_at`, `superseded_at`, `created_at`. Superseded rows stay so log `vial_id` values still resolve.

**vial_people** — `vial_id`, `person_id`, `sort_order`. Unique person among vials with `superseded_at` null.

**log_entries** — new table, backfilled from `uses`, columns in the table above. The `uses` table stays until M5 removes its routes.

**account_syringe** — new table, one row: `volume_ml` > 0, `capacity_iu` > 0. The v7 default syringe profile supplies it. Quantity and `archived_at` on `syringe_profiles` are ignored. The v2 route is still `/syringe`.

Global sqlite is unchanged.

## Migration on unlock (v7 → v8)

Run inside the existing exclusive unlock. Copy ciphertext to `.enc.bak` the way later migrations already do.

1. Every profile becomes a person. Keep the stored name, including **Default**. `removed_at` null. Exception: a store whose only profile is the seeded **Default**, with zero compounds and zero uses, gets an empty `people` table. That is a new account. The old `profiles` row stays so the v0.3 profile routes still run until M5.
2. Ensure Tirzepatide and Retatrutide exist and are visible. A custom peptide referenced by a compound or a use stays visible. Semaglutide and liraglutide, when nothing references them, are `removed_at` now.
3. Each use becomes a log row. Copy `iu`, computed volume, `peptide_mg` → `dose_mg`, syringe snapshot, `used_at` → `logged_at`, profile id and name. `is_last_draw` false. Snapshot peptide, BAC, vial mg, concentration, and vial name from the compound the use points at. Missing compound: leave vial snapshots blank and `vial_id` null; keep the dose.
4. Current vial, per person: among compounds with `archived_at` null that include that person, pick the latest `compounded_at`. That compound stays current for them. A person whose newer vial is a different compound is removed from the older compound's people. A compound that no longer has anyone, and every archived or closed compound, gets `superseded_at`.
5. `usage_offset_mg` = `−Σ adjustment.delta_mg` for that compound. No adjustments → 0.
6. `probably empty` is not inferred. Migrated rows are not last draws.
7. Lid color is empty on migrated vials.
8. The default syringe profile's `volume_ml` and `capacity_iu` become the account syringe. Other syringe rows are unused.

After migration, Inventory shows at most one current vial per person. History is the log list. BAC bottles and syringe counts are not shown.

## API

Cookie auth, same error envelope as [DESIGN.md](DESIGN.md). Validation is **422** with `error.fields`. Unauthenticated is **401**.

Success stays `{ "statusCode", "data" }`.

| Method | Path | Behavior |
| --- | --- | --- |
| GET | `/health` | Unchanged |
| GET | `/auth/google/start` | Unchanged |
| GET | `/auth/google/callback` | Unchanged |
| POST | `/auth/login`, `/auth/register`, `/auth/logout` | Unchanged. Login screen does not lead with them |
| GET | `/me` | Email, `has_password`, `has_google`. M1 through M4 keep `remainder` and `open_vials` so the old Home page still runs. M5 drops those two fields |
| GET | `/me/export`, backup routes | Unchanged |
| GET/POST | `/people` | Visible people, `created_at` ascending. POST `{ name }` |
| PATCH | `/people/{id}` | Rename. 422 on duplicate visible name |
| POST | `/people/{id}/remove` | Sets `removed_at`, unassigns from the current vial |
| POST | `/people/{id}/restore` | Clears `removed_at`. 422 on name clash |
| GET/POST | `/peptides` | Visible list. POST `{ name }` seeds nothing else |
| POST | `/peptides/{id}/remove` | Hide from the picker |
| GET | `/syringe` | The account syringe |
| PUT | `/syringe` | `{ volume_ml, capacity_iu }`, both > 0 |
| GET | `/vials` | Current vials only, with `mg_left`, per-person `drawn_mg`, `probably_empty`, people in order |
| POST | `/vials` | Create current vial. Body below. Supersedes as in the vial rules |
| GET | `/log/defaults?person_id=` | Prefill payload |
| GET | `/log?person_id=&before=&limit=` | That person's rows, `logged_at DESC, id DESC`. Default limit 50, cap 100 |
| POST | `/log` | Create. Snapshots from the chosen current vial and the account syringe |
| GET/PATCH/DELETE | `/log/{id}` | Read, edit, delete. DELETE is 204 |

`POST /vials` body:

```json
{
  "peptide_id": "…",
  "person_ids": ["…", "…"],
  "peptide_mg": 10,
  "bac_water_ml": 2,
  "lid_color_id": null,
  "lid_color_name": "Blue"
}
```

Send `lid_color_id` for an existing color, or `lid_color_name` to find-or-create. One of them is required. Response includes `display_name`.

`GET /log/defaults` data:

```json
{
  "person_id": "…",
  "logged_at": "2026-11-16T10:18",
  "iu": 25,
  "is_last_draw": false,
  "vial_id": "…",
  "probably_empty": false,
  "source": { "log_id": "…", "logged_at": "2026-11-09T09:00" }
}
```

`logged_at` in this payload is the server's "now" suggestion; the client may overwrite it with the device clock before save. `source` is null, and `iu` is null, when that person has no log rows. `vial_id` is their current vial or null. `probably_empty` follows the last-draw rule for that vial.

`POST /log` body: `person_id`, `vial_id`, `iu`, `logged_at`, `is_last_draw`, optional `notes`. The server loads the vial and the account syringe and writes the snapshot. 422 when the person is missing, the vial is not current, or IU is not a positive one-decimal number. 422 is not used for amount left.

PATCH uses the same fields. The row's syringe snapshot stays.

v0.3 routes stay mounted through M4: `/compounds`, `/uses`, `/bac-bottles`, `/syringes`, `/peptide-types`, `/profiles`. M5 removes them. v2 screens call only the v2 paths.

## Acceptance

These are the behaviors a later implementation has to show. They are product tests, not a script to run now.

**One tap.** Noah's latest row is Nov 9, 25 IU, on his current vial. Opening the app on Nov 16 shows Noah, today's date, that vial, 25 IU, and "Same as Nov 9". Save writes a new row for Nov 16 and leaves the Nov 9 row in the list.

**Another person's vial.** Noah selects Sam's current vial and saves. The row's person is Noah. Sam's vial stays Sam's. Sam's `drawn_mg` is unchanged. Noah's dose counts in that vial's `mg_left`.

**Past the label.** The convenience math says 1 mg left. A dose of 5 mg saves. The card shows the result past the label. No 422.

**Last draw.** Noah checks Last draw and saves. Log and Inventory say the vial is probably empty. Recompound opens the modal with that vial's peptide, mg, BAC, people, and lid. Saving it makes the new vial the only current one for those people. The old name, BAC, vial mg, and dose mg remain on the earlier log rows.

**Recalculate.** From the same banner, Recalculate opens pepcalc with the vial mg and Noah's latest mg and IU. Use this mix returns to the vial modal with a new BAC. People and lid are unchanged until the user edits them.

**First visit.** A new Google account lands on Log with a name field. After the name is saved, the screen asks for a vial. After the vial is saved, the IU field is empty and there is no "Same as" line.

**Shared replace.** Vial X is Noah and Sam. A new vial lists only Noah. Noah's current vial is the new one. Sam's current vial is still X, and X's name no longer includes Noah.

## Decisions recorded here

- Latest log row is the prefill. The new row's date is today.
- The log row is self-contained. Superseded vials stay in the file and off the screen.
- Empty means the user marked Last draw, not that the math hit zero.
- Google login, encrypted sqlite, dose math, and the SvelteKit static SPA stay.
- This file does not change `APP_VERSION`. Each implementation branch bumps it to the version in the checklist.
- v8 tables sit beside the v0.3 tables. Old routes stay until M5. New routes do not write the old tables.
